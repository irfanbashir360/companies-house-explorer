# Open-Source Launch Checklist

Use this checklist to run a coordinated multi-platform launch for `companies-house-explorer`.

## T-3 Days: Preparation

### Repository Readiness

- [ ] Confirm `README.md`, `LICENSE`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, and `SECURITY.md` are complete.
- [ ] Ensure `.env.local` is ignored and no secrets are committed.
- [ ] Review `package.json` metadata (`description`, `repository`, `license`, `keywords`).
- [ ] Validate issue and PR templates under `.github/`.

### Visual and Content Assets

- [ ] Capture product screenshots using `docs/screenshot-checklist.md`.
- [ ] Prepare a short demo GIF/video (10-30 seconds) for social posts.
- [ ] Finalize copy from `docs/launch-copy.md` with final repository URL.
- [ ] Prepare link-in-bio/landing links for Instagram.

### Quality Verification

- [ ] Fresh clone test from a separate folder.
- [ ] Run `npm install`, `npm run lint`, and `npm run build`.
- [ ] Confirm setup steps work exactly as written in README.

## T-1 Day: Staging

- [ ] Create and tag first release draft on GitHub.
- [ ] Pre-write and save all platform posts.
- [ ] Identify target Reddit communities and read posting rules.
- [ ] Prepare initial `good first issue` labels/tasks.

## Launch Day: Publishing Sequence

### 1) GitHub (Source of Truth)

- [ ] Publish release notes.
- [ ] Pin repository (if applicable).
- [ ] Ensure README hero section and screenshots are visible.

### 2) LinkedIn + X (Primary Distribution)

- [ ] Publish LinkedIn long-form post.
- [ ] Publish X thread immediately after LinkedIn.
- [ ] Reply to first comments quickly to boost visibility.

### 3) Instagram (Awareness Layer)

- [ ] Publish feed post with project visuals.
- [ ] Publish 3 supporting story frames with repo CTA.

### 4) Reddit + dev.to/Hashnode (Community + Depth)

- [ ] Publish Reddit post with practical context and clear ask for feedback.
- [ ] Publish dev.to/Hashnode article or teaser with repo link.

## T+1 to T+3 Days: Follow-Through

- [ ] Respond to all comments and questions.
- [ ] Convert recurring feedback into GitHub issues.
- [ ] Triage incoming issues (`bug`, `enhancement`, `good first issue`).
- [ ] Re-share updates or mini progress notes (new stars, first PRs, roadmap).

## Metrics to Track

Track daily for the first week.

### Repository Metrics

- [ ] GitHub stars
- [ ] Forks
- [ ] Watchers
- [ ] New issues opened
- [ ] Pull requests opened

### Traffic Metrics

- [ ] GitHub profile/repo visits
- [ ] Link clicks from each platform
- [ ] README unique views (if available)

### Engagement Metrics

- [ ] LinkedIn impressions and comments
- [ ] X thread impressions, reposts, replies
- [ ] Instagram reach, story taps, link clicks
- [ ] Reddit upvotes and comment quality
- [ ] dev.to/Hashnode reads and reactions

## Week 1 Success Targets (Editable)

- [ ] 50+ GitHub stars
- [ ] 5+ actionable issues from community feedback
- [ ] 1-3 external PRs or contributor expressions of interest
- [ ] At least one follow-up post with roadmap updates
